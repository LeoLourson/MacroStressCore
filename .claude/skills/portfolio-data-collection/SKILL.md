# Сбор данных для портфеля

Портфель собирается под конкретное событие и дату снимка. Данные для него берутся из
публичных источников, а чего в них нет — помечается авторской оценкой, а не подставляется
молча. Источники, из которых в этом репозитории уже что-то добыто, перечислены в конце.

## 1. Что собираем: тип и поля определяет реестр

Платформа расширяема: типы инструментов, их поля и схемы объявлены плагинами, а не списком
в этом файле. Захардкоженный перечень семейств и полей устареет на первом же новом плагине,
поэтому первым шагом читаем каталог:

```bash
uv run --frozen python -c "import json;from msa.platform.catalog import asset_types;print(json.dumps(asset_types(),ensure_ascii=False,indent=1))" > asset-types.json
```

Тот же каталог отдаёт `GET /v1/asset-types` (открыт без ключа) — брать его оттуда, когда
работаешь через API. На каждый тип там есть `terms_schema`, `position_schema` и `editor` —
группы `group_id`/`title` с полями `name`, `unit`, `required`, `default`, `minimum`, `maximum`.
Схемы и редактор строже любого описания: они и есть контракт приёма данных.

Как читать `editor` типа:

- Группа `position` («Позиция банка») — экспозиция: `ead`, `lgd`, `ccf`, `import_share`. Она
  есть у кредитных типов, значения задаёт аналитик, из раскрытия они не берутся.
- Остальные группы названы по месту числа: `terms` — условия инструмента, `statement` —
  отчётность заёмщика, `covenants` — таблица ковенантов. `group_id` и есть цель поля.
- Поле `required=True` без `default` обязательно; поле с `default` можно не задавать, но
  пропуск означает подстановку допущения, и это надо отметить в отчёте.
- Расшифровка каждого поля — в исходнике семейства: `src/msa/plugins/<плагин>/families/` для
  кредитных типов (там же `source` поля — `terms`, `statement`, `market`), `editor.py` — для
  остальных. `identity` типа (например `ticker`) означает, что несколько позиций с одним
  значением — это лоты одной бумаги, у них общие условия и котировки.
- `asset_types()["flags"]` и `review_flags` — что означают коды в результате. Свои не выдумывать.

Деньги — млн ₽ (`RUB_million`), ставки — доли (`0.2`, не 20), месяцы — номер месяца горизонта,
а не дата. Горизонт — 12 месяцев. Единицы — в `asset_types()["units"]`.

## 2. Раскладка одной позиции

Строка портфеля повторяет редактор: `position_id` (латиница, до 40 знаков), `name`,
`instrument_type`, `okved` (нужен, когда `issuer_required`), `currency`, `values` по именам
полей из шага 1 и `tables` — только для табличных полей.

`values` собирается из экспозиции банка (`ead`, `lgd`, `ccf`, `import_share`) и полей
семейства. Поле с `source="terms"` — договор, `"market"` — рынок на дату оценки, остальные —
отчётность заёмщика. Признак одинаков во всех семействах, поэтому источник не угадывается.

## 3. Откуда берутся числа

Порядок обхода источников: сначала орган раскрытия, потом первоисточник эмитента, потом
агрегатор — и только потом оценка.

- Даты снимка и список нужных показателей задаёт событие и постановка: см. события в
  `demo/historical/<случай>/events/` (и `demo/historical/mortgage-2023/event.json`) и
  `docs/manual-tests/manual-test-*.md`. В постановке прямо сказано, что берётся из декларации, что — из
  отчётности, а что запрашивается у финансистов.
- Застройщик: проектная декларация, раздел 19.6 (`19.6.1.4` — сумма кредита, `19.6.1.5` —
  задолженность на отчётную дату, `19.6.1.6` — неиспользованный остаток), `18.1.1` — стоимость
  строительства, `17.1`/`17.2` — график готовности и срок передачи, `19.2`/`19.4` — банк эскроу
  и уполномоченный банк, `19.7` — ДДУ, площади и цены. Ставки в форме нет.
- Эмитент: МСФО и пресс-релизы; долг, эскроу, проектное финансирование, средневзвешенная
  ставка — из примечаний. Котировки, индексы и беты — MOEX ISS.
- Рынок: помесячная статистика Банка России для калибровки силы сценария и сверки с фактом.
- Групповые и отраслевые данные для позиций других типов — по тому же принципу: сначала
  раскрытие эмитента, затем агрегаторы.
- Квартальная отчётность застройщика по 214-ФЗ (приказ 656/пр) даёт собственные средства,
  нормативы Н1/Н2/НСС и освоение средств. Она публикуется в ЕИСЖС; без браузера недоступна.

Не раскрывается почти никогда: ставка проектного кредита, помесячный график выборки и затрат,
остатки на эскроу по объекту, ковенанты. Это запрашивается у финансистов; если их ответа нет,
величина оценивается и помечается как допущение.

## 4. Доступ к ЕИСЖС

Карточки объектов и внутренние пути (`/сервисы/...`, `/portal-kn/api/...`) закрыты антиботом:
403 с заголовком `X-SP-CRID`. Отказ не зависит от VPN, cookies, `Authorization`, клиента и
заголовков — не тратить на обход время, искать открытый путь:

- `/api/ext/file/<хеш>?filename=<имя>.pdf` отдаёт декларации без капчи и авторизации. Хеш — это
  hex имени исходного файла (`projectdecl.docx.izd` = `70726F6A6465636C2E646F63732E697A64`)
  плюс 32 шестнадцатеричных знака. Подобрать нельзя, но прямые ссылки попадают в поисковый
  индекс — искать по номеру декларации и адресу объекта.
- Зеркала застройщиков и региональных порталов раздают те же файлы напрямую, например
  `omsk.sibdom.ru/file/download/<id>/?key=<key>`. Подпись зеркала бывает неверной: сверять
  содержимое PDF с названием.
- Агрегаторы деклараций дают помесячные срезы разделов 18 и 19. Данные третьих лиц: сверить
  хотя бы одну строку с самим PDF, прежде чем брать массив.

Скачанное складывать рядом с отчётом о сборе (`docs/` внутри рабочей папки), а не в `demo/`.
Имена — `<что>-<номер>-<дата>.pdf`: версия декларации должна быть видна из имени.

## 5. Происхождение числа

Каждое число несёт запись `evidence`: `historical_estimate` — величина раскрыта, указываются
документ и раздел; `expert_assumption` — не раскрыта, указываются автор и дата оценки. Через
редактор (`POST /v1/demo/portfolios/draft`) числа попадают в снимок как допущения аналитика;
для каталога источник задаётся явно, как `_value(...)` и `_estimate(...)` в `demo/build_etalon.py`.

Правило платформы — отсутствие молчаливых значений по умолчанию: пропущенный обязательный
вход ломает приём, пропущенный необязательный подставляет допущение, и его признак доходит до
результата. Поэтому в отчёте отдельным списком идёт то, что оценено, с причиной.

## 6. Сборка и проверка

Материализация каталога — генератор, а не рукописный JSON: для портфелей пилота это
`demo/build_etalon.py` — он собирает `PortfolioDraft`, вызывает `msa.api.portfolio_draft.build`,
проверяет `check_bundle` и раскладывает результат по путям исторического случая (заголовки в
`demo/historical/etalon/{portfolios,snapshots}/`, части по плагинам в
`src/msa/plugins/<плагин>/demo_data/historical/etalon/{portfolios,snapshots}`). Новый реальный
случай получает свою папку `demo/historical/<случай>/` того же устройства (`events/`,
`portfolios/`, `snapshots/`, `sources.json`, `research/`) и `metadata.synthetic: false`; см.
`demo/README.md`.

```bash
uv run --frozen python -m demo.build_etalon --check   # сверить, не меняя; код 1 при расхождении
uv run msa-plugin check                               # соответствие плагинов
uv run --frozen pytest
```

Сверки, которые ловят ошибку разбора до расчёта:

- по каждому кредиту отдельно и по сумме: задолженность + неиспользованный остаток = сумма
  кредита;
- сопоставление с независимым источником хотя бы на одном объекте;
- срок передачи и график готовности против даты снимка: что попадает в 12 месяцев, что нет;
- сумма по одной декларации не равна лимиту программы из пресс-релиза: программа — несколько
  объектов ЕИСЖС.

## 7. Прочие источники репозитория

Сбор пилота «Эталон» лежит в `demo/historical/etalon/research/` и годится как образец: `README.md` — сводка
и ограничения, `project-data.md` — что раскрыто по объекту и что закрыто, `group-financials.md`
и `group-operations.md` — отчётность эмитента и рынок, `portfolio-draft.md` — значения по полям
платформы, `demo/historical/etalon/sources.json` — источники машинно-читаемым списком. Постановки на другие портфели —
в `docs/manual-tests/`.
