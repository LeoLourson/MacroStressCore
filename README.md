# MacroStress Core

Стресс-тест портфеля по тексту события — на платформе расширяемых расчётов и агентов.
Аналитик вводит текст (постановление, решение регулятора, санкции) и своими словами
описывает силу события. LLM строит граф передачи шока «событие → канал → отрасль → фактор»
и предлагает сценарий. Аналитик подтверждает граф и сценарий. Затем каждая затронутая
позиция считается моделью своего типа на общей матрице сценариев: кредит — детерминированная
помесячная модель заёмщика (P5/P50/P95, ковенанты, ликвидность, вклад каналов, обратный
стресс-тест), акции — факторный стресс с валютным фактором. Итоги по срезам портфеля
(кредитные потери, рыночный результат) получаются сложением внутри общих реализаций, и срезы
между собой не складываются. Отчёт, в котором каждое число ссылается на метрику,
утверждает риск-менеджер. По рассчитанному прогону можно задать вопрос: ответ строится
только на числах прогона, прочитанных через MCP-инструменты.

Типы инструментов, расчётные модели, факторы, срезы, экраны результатов и агенты
подключаются **плагинами** без правки ядра. См. [docs/plugins.md](docs/plugins.md).

## Запуск (Windows, без Docker)

```powershell
.\msa.ps1 up mock        # без LLM: граф по отраслям портфеля, расчёт настоящий
.\msa.ps1 up deepseek    # DeepSeek API, ключ в DEEPSEEK_API_KEY; только демо-портфели
.\msa.ps1 up local       # OpenAI-совместимый сервер на 127.0.0.1:1234 (LM Studio, vLLM)
.\msa.ps1 status | logs | down
.\msa.ps1 rehearse RECYCLING-FEE MORTGAGE-DOWN-PAYMENT   # репетиция линии на поднятом стенде
```

`up` создаёт `.env` с локальными ключами и поднимает PostgreSQL 16 (порт 5433). Затем он
применяет миграцию, загружает демо-каталог (портфели, снимок данных, события), собирает
`ui/web` и запускает API с интерфейсом на http://127.0.0.1:8091.

## Демо-каталог

Все данные синтетические, на 11.09.2026. Каждое событие подготовлено для своего портфеля:
при выборе события интерфейс подставляет этот портфель, если аналитик не выбрал другой. В
профиле `mock` каузальный шаг отвечает готовым графом и сценарием события (`mock_answer` в
файле события).

Для содержательной демонстрации начните с трёх смешанных деловых историй ниже. В них 15 вымышленных
компаний, неодинаковые размеры позиций, общие эмитенты, запас ликвидности, ковенанты и
разные сроки передачи шока. Подробный маршрут показа и допущения — в
[demo-stories.md](docs/demo-stories.md). Прежние тематические и технические примеры сохранены.

`MULTI-ASSET`, `ATYPICAL-BORROWERS` и `LOAD-TEST` записаны вручную
(снимок `SYNTHETIC-2026-09-11`). Тематические

вместе с ответами профиля `mock`; портфель, добавленный позже, получает свой снимок
(`SGZH-CREDIT` — `SYNTHETIC-SGZH-2026-09-11`):

Три смешанных и шесть однородных портфелей используют отдельный снимок
`SYNTHETIC-STORIES-V1-2026-09-11` (23 вымышленные компании).
Их компании и описания заданы в `demo/story_catalog.json`, финансовые исходные строки —

```powershell
uv run --frozen python -m demo.build_catalog --check   # сверить (то же делает pytest)
uv run --frozen python -m sanity M                     # каждое событие на своём портфеле
```

## Разработка

```powershell
uv sync --frozen                       # Python 3.12, зависимости из uv.lock
uv run --frozen pytest                 # тесты платформы и плагинов (src/msa/plugins/*/tests)
uv run --frozen ruff check . ; uv run --frozen ruff format --check .
uv run --frozen lint-imports           # граница ядра и плагинов: правила импорта
uv run --frozen python -m sanity       # проверки здравого смысла на синтетике (docs/sanity-report.md)
cd ui/web; npm ci; npm run dev         # интерфейс с прокси на API :8091
npm run build                          # манифест плагинов, совместимость UI-плагинов, типы, сборка
```

Плагины:

```powershell
uv run msa-plugin new asset <id>       # шаблон типа инструмента с моделью, тестами, демо-данными
uv run msa-plugin new agent <id>       # шаблон агента с MCP-инструментом, промптом и UI-видом
uv run msa-plugin check [<id>]         # проверка соответствия плагина
uv run msa-plugin demo-run <id>        # демо-расчёт: P5/P50/P95 по позициям и срезам
uv run msa-plugin ui-manifest          # манифест UI-плагинов (npm run build делает это сам)
```

Плагин — папка `src/msa/plugins/<id>/` (код, тесты, демо-данные, промпты, README) и, по
желанию, `ui/web/src/plugins/<id>/`. Новый плагин создаётся без правки вне этих папок;
правила границы — в [docs/plugins.md, раздел 8](docs/plugins.md#8-границы-и-совместная-работа).

Техническое задание на систему в её текущем виде:

- [для разработчика](docs/tz/developer.md) — архитектура и границы ядра, модель данных, шаги
  процессов, модели, API и MCP, хранение, безопасность, развёртывание, приёмка; подробно —
  расширение плагинами;
- [обзорная версия](docs/tz/overview.md) — для читателя без опыта работы с кодом: назначение,
  ход прогона, как читать P5/P50/P95, почему результату можно доверять, ограничения;
- [математика расчётов](docs/tz/math.md) — какая математика стоит за числами и зачем: путь от
  события до отчёта, соглашения и словарь; формулы сценариев, передачи шока, кредитных и
  долевых моделей, портфеля и проверки чисел — в файлах [docs/tz/math/](docs/tz/math/).
