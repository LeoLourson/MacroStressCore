## 1. Зачем нужна система

Инвестор или банк держит портфель разных активов: кредиты компаниям, облигации, проектное финансирование стройки, кредиты лизинговым компаниям, акции. Регулярно происходят события, которые могут этот портфель затронуть: повышение ключевой ставки, новый утилизационный сбор, санкции, падение курса рубля, изменение условий льготной ипотеки и тд.

Сегодня аналитику нужно прочесть документ, понять, каких компаний он касается, и вручную
прикинуть последствия. Это долго, и выводы трудно проверить.

**MacroStress Core** делает это за аналитика, но под его контролем:

1. читает текст события;
2. строит схему того, как событие распространяется по экономике: через какие каналы, на
   какие отрасли и на какие показатели компаний;
3. предлагает сценарий — насколько сильно изменятся эти показатели;
4. после подтверждения аналитиком считает каждую затронутую позицию портфеля и портфель
   целиком;
5. пишет отчёт с рекомендациями, где каждое число можно проверить;
6. передаёт отчёт риск-менеджеру на утверждение;
7. и отвечает на вопросы по результатам.

## 2. Кто с ней работает

| Кто | Что делает в системе |
|---|---|
| **Аналитик** | запускает стресс-тест, проверяет и при необходимости исправляет схему события и сценарий, задаёт вопросы по результатам |
| **Риск-менеджер** | читает отчёт и принимает решение: утвердить, вернуть на доработку с причиной или отклонить |
| **Администратор** | загружает рабочие портфели банка и данные о компаниях |
| **Разработчик модулей** | добавляет новые типы активов, модели расчёта и помощников-агентов, не трогая основу системы |

## 3. Как проходит стресс-тест

```
 Текст события ─► Схема влияния и сценарий ─► Проверка ─► Аналитик подтверждает
                     (LLM)                    (правила)     (остановка)
      ─► Расчёт каждой позиции ─► Итог по портфелю
      ─► Отчёт с рекомендациями ─► Риск-менеджер подтверждает ─► Публикация
                (правила)                      (остановка)
```

**Шаг 1. Событие.** Аналитик вставляет текст, ссылку на официальный сайт или загружает
документ (PDF, Word). Он может своими словами описать силу события: «ставка вырастет на 2–3
пункта». Система разбивает текст на пронумерованные фрагменты, чтобы потом ссылаться на
них.

**Шаг 2. Схема влияния и сценарий.** Языковая модель (LLM) строит схему «событие → канал →
отрасль → показатель». Например: «утилизационный сбор → цена импортной спецтехники →
дистрибьюторы техники (код отрасли 46.63) → себестоимость». У каждой связи есть цитата из
текста, сила влияния и задержка в месяцах. Затем модель предлагает сценарий: насколько
изменится каждый показатель. Если текст не называет величину, модель оценивает её
диапазоном и помечает как своё допущение.

**Шаг 3. Проверка.** Правила проверяют ответ модели: схема без циклов, у каждой связи есть
источник, каждая цепочка доходит до показателя, который умеет читать модель расчёта, для
каждой затронутой компании задан сценарий. Ошибки возвращаются модели на исправление.

**Шаг 4. Аналитик подтверждает.** Расчёт не начнётся, пока аналитик не посмотрит схему и
сценарий. Он может поправить связи, силу влияния, задержки и величины. Всё, что изменил
аналитик, записывается как его допущение. Система заранее показывает, какой шок получит
каждая позиция.

**Шаг 5. Какие позиции задеты.** Позиция затронута, если схема ведёт в отрасль её
заёмщика (сравниваются коды ОКВЭД) или сценарий прямо двигает её рыночный показатель —
индекс акций или курс валюты. Незатронутые позиции не считаются, но учитываются, чтобы
показать, какую долю портфеля задело событие.

**Шаг 6. Сценарное моделирование.** Система строит тысячи согласованных вариантов будущего (по умолчанию 8192) из подтверждённых диапазонов. Все позиции считаются на одних и тех же вариантах.

**Шаг 7. Расчёт позиций.** Каждая позиция считается моделью своего типа (раздел 4). Если
одна позиция не посчиталась, остальные считаются дальше, а причина показывается.

**Шаг 8. Итог по портфелю.** Потери складываются внутри каждого варианта будущего, и
только потом считается худший, типичный и благоприятный исход. Кредитные потери и
рыночный результат акций показываются отдельно и между собой не складываются: это разные
по смыслу величины.

**Шаг 9. Отчёт.** Система пишет отчёт: итоги, рекомендации, ограничения, допущения и их
авторы. Рекомендации выдаются по правилам (например, «покрытие процентов ниже 1 —
реструктуризировать долг»). Каждое число отчёта связано с расчётом; отчёт с
непроверяемым числом не пропускается.

**Шаг 10. Решение риск-менеджера.** Отчёт публикуется только после его решения. Вернуть
или отклонить отчёт можно только с указанием причины.

**Шаг 11. Вопросы по результатам.** После расчёта можно спросить: «Почему выросли потери
по дистрибьютору техники?» Ответ строится только на числах этого прогона, которые LLM читает
через специальные инструменты. Если LLM назвал число, которого нет в расчёте, ответ
заменяется сводкой без LLM.

## 4. Что система считает

### Кредиты и облигации

Для каждого заёмщика строится помесячная модель на год вперёд: выручка, затраты, прибыль
до процентов и налогов (EBITDA), расчёты с покупателями и поставщиками, налог,
инвестиции, долг и проценты, деньги на счетах, кредитная линия. Затем:

- **вероятность дефолта (PD)** — по финансовым коэффициентам заёмщика;
- **ожидаемые потери** и их **рост из-за события** — главная денежная величина;
- **ковенанты** — вероятность нарушить условие кредитного договора (например, «долг не
  больше трёх годовых EBITDA»), запас до нарушения и месяц, когда оно случится;
- **ликвидность** — хватит ли денег, не понадобится ли дополнительное финансирование;
- **вклад каналов** — какая часть роста потерь пришла через ставку, курс, спрос или затраты;
- **обратный стресс-тест** — во сколько раз должен усилиться сценарий, чтобы ковенант
  нарушился;
- для облигаций — **изменение стоимости** выпуска.

Отдельные модели есть для обычной компании, облигаций с фиксированным и плавающим
купоном, проектного финансирования жилья с эскроу-счетами и лизинговой компании.

### Акции

Цена акции на конец года зависит от движения рынка, отрасли эмитента сверх рынка и
собственного риска компании; акция в иностранной валюте переоценивается по курсу.
Считаются стоимость, результат с дивидендами, потери и вклад каждого фактора.

### Портфель

По каждому срезу (кредитные потери, рыночный результат) — распределение потерь, худшие
5 % исходов, вклад каждой позиции в худшие исходы, концентрация, доля портфеля, которую
удалось посчитать.

## 5. Как читать результат

Система не даёт одно число «потери будут 12 млн». Будущее неопределённо, поэтому каждая
величина — диапазон из трёх чисел, которые всегда показываются вместе:

| Обозначение | Смысл |
|---|---|
| **P5** | благоприятный исход: в 5 % вариантов лучше |
| **P50** | типичный исход: половина вариантов лучше, половина хуже |
| **P95** | неблагоприятный исход: только в 5 % вариантов хуже |
| **ES95** | средние потери в худших 5 % вариантов |

У результата есть **статус**: «в порядке», «нужна проверка» (модель сделала упрощение,
которое должен принять человек), «без калибровки» (есть балл риска, но нет денежной оценки),
«неполный», «ошибка». Рядом с каждым числом можно открыть его происхождение: из каких
данных, на какую дату, по какому сценарию оно получено.

## 6. Почему результату можно доверять

| Механизм | Что он гарантирует |
|---|---|
| Два обязательных решения человека | LLM не может сам запустить расчёт и опубликовать отчёт |
| Цитаты у каждой связи схемы | видно, на каком месте текста основано влияние |
| Никаких молчаливых умолчаний | если данных нет, позиция не считается «как будто ноль»; любое допущение помечено и видно в отчёте |
| Каждое число с источником | у данных есть автор и дата; у числа отчёта — ссылка на расчёт |
| Проверка чисел отчёта и ответов | текст с числом, которого нет в расчёте, не принимается |
| Общие сценарии для всех позиций | потери разных позиций согласованы и складываются честно |
| Воспроизводимость | тот же расчёт с теми же данными даёт те же числа; версии моделей зафиксированы |
| Журнал | каждое действие LLM, инструмента и человека записано |
| Два контура | рабочие данные банка не уходят во внешнюю LLM-модель |
| Точность | система оценивает свою численную погрешность и помечает результат, если она велика |

## 7. Как система расширяется

Главная идея архитектуры: **неизменная основа (ядро) и подключаемые модули (плагины)**.
Ядро умеет общее: хранить портфели и данные, строить сценарии, запускать расчёты, собирать
итоги, писать проверяемый отчёт, останавливаться для решения человека, вести журнал. Всё,
что относится к конкретной предметной области, приходит из модулей.

Сравнение: ядро — как электрическая розетка стандарта, модули — как приборы. Новый прибор
не требует перекладывать проводку.

### Что можно добавить модулем

| Что добавляется | Пример | Где появляется само |
|---|---|---|
| Тип актива | депозит, фьючерс, паи фонда | проверка портфеля, форма ввода, каталог |
| Модель расчёта | модель переоценки фьючерса | расчёт, выбор модели при запуске |
| Показатель, который двигает сценарий | цена нефти, курс юаня | сценарий, схема события, подсказка для LLM |
| Срез портфеля | «процентный риск банковской книги» | итог портфеля, отчёт |
| Раздел отчёта и правила рекомендаций | «если стоимость фьючерса упала больше чем на 10 % — захеджировать» | отчёт |
| Помощник-агент | «проверить концентрацию хвостового риска» | этапы процесса, журнал |
| Инструмент для агента | «сводка по срезу» | доступен только объявившему его агенту |
| Экран результата | собственная карточка позиции | интерфейс |

### Какие правила соблюдает модуль

- Модуль живёт в своей папке и **не требует правки ядра**. Если требует — значит, в ядре
  не хватает точки подключения, и её добавляют отдельно, для всех модулей сразу.
- Модуль объявляет, какие данные ему нужны, — ядро само находит их на дату оценки.
- Модель расчёта не ходит в базу данных, в интернет и к LLM: она получает подготовленные
  данные и сценарии. Поэтому её легко проверить и повторить.
- Каждое число модуля — с единицей измерения и источником.
- Помощник-агент подключается к одной из четырёх точек процесса (после разбора события,
  перед подтверждением сценария, после расчёта, перед отчётом). Он видит только то, что
  разрешено в этой точке, пишет только в своё пространство, не меняет расчёт и отчёт и не
  может обойти решения человека. Его сбой не останавливает прогон.
- Модуль несёт свои тесты, демонстрационные данные и описание.

### Как проверяется модуль

Есть готовые шаблоны: одна команда создаёт заготовку типа актива или агента, которая сразу
проходит проверку. Проверка соответствия автоматически убеждается, что модуль:
правильно объявлен; считает свой демонстрационный пример; даёт одинаковый результат при
повторе и при другом порядке позиций; складывается в итоги портфеля; для агентов —
встраивается во все процессы. Отдельная проверка следит, что ядро не упоминает
конкретные модули, а модули не лезут во внутренности ядра.

### Какие модули есть сейчас

| Модуль | Что даёт |
|---|---|
| Кредит | пять типов: корпоративный кредит, облигации с фиксированным и плавающим купоном, проектное финансирование с эскроу, кредит лизинговой компании |
| Акции | обыкновенные акции, стресс по рынку, отрасли и курсу |
| Рынок | общий валютный фактор и срез рыночного результата для рыночных активов |
| Исследование | пример трёх помощников-агентов (выключены по умолчанию) |

### Куда развиваться дальше

Следующие семейства активов по очереди: деньги и депозиты, фонды, товары, производные
инструменты, опционы, секьюритизация, недвижимость, страхование. Каждое — отдельный модуль.

## 8. Требования к системе

### 8.1. Что система должна делать

1. Принимать событие текстом, ссылкой на разрешённый сайт или документом PDF/Word.
2. Строить схему влияния и сценарий с цитатами из текста; помечать величины, которые LLM
   оценил сам.
3. Автоматически проверять схему и сценарий и возвращать ошибки LLM на исправление.
4. Останавливаться для подтверждения аналитиком; давать исправить схему и сценарий и
   показывать, какой шок получит каждая позиция.
5. Определять затронутые позиции по отраслям и рыночным показателям.
6. Считать каждую затронутую позицию моделью её типа на общих сценариях.
7. Собирать итоги по срезам портфеля, показывать покрытие и концентрацию.
8. Писать отчёт с рекомендациями, где каждое число проверено.
9. Останавливаться для решения риск-менеджера; принимать решение с причиной.
10. Отвечать на вопросы по результатам только числами прогона.
11. Показывать происхождение любого числа и журнал вызовов LLM и инструментов.
12. Давать вводить и редактировать портфель в форме, построенной по описанию типа актива.

### 8.2. Каким требованиям отвечает

| Область | Требование |
|---|---|
| Безопасность | вход по персональным ключам с ролями; внешняя LLM-модель только на демонстрационных данных; инструменты агентов только читают; ограничения числа запусков на ключ |
| Надёжность | после перезапуска сервера прогон продолжается с последнего шага, без повторных запросов к LLM; сбой одной позиции не ломает остальные |
| Воспроизводимость | фиксируются версии моделей, данные, сценарий и начальное значение генератора |
| Прозрачность | каждое число с происхождением; каждое допущение с автором |
| Расширяемость | новый модуль подключается без правки ядра |
| Производительность | до пяти прогонов одновременно; портфели в сотни позиций |
| Интерфейс | работает в браузере; диапазоны P5/P50/P95 всегда вместе; состояние и тяжесть риска подписаны словом или значком, а не только цветом; фирменный красный МТС — только для айдентики и утверждения |

### 8.3. Режимы работы LLM

| Режим | Когда |
|---|---|
| Модель внутреннего | рабочий режим |
| Внешний сервис DeepSeek | только демонстрационные данные |
| Без LLM | демонстрация и проверки: схема берётся готовой, расчёт настоящий |

## 9. Демонстрационный стенд

Стенд запускается одной командой на компьютере с Windows. Все данные вымышленные, на
11 сентября 2026 года: 18 портфелей и 21 событие, каждое подобрано под свой портфель.
Лучше всего начинать с трёх деловых историй:

| Портфель | Что внутри | События |
|---|---|---|
| «Торговый коридор» | импортёры, экспортёры, склады, перевозчик | задержки грузов на границе; восстановление поставок |
| «Региональный центр» | жилой проект с эскроу, подрядчики, теплосети | неоплата принятых работ; возобновление стройки |
| «Повседневный спрос» | продукты, магазины, производитель техники | переход покупателей к экономии; подорожание молока |

Есть и тематические примеры: валютный и процентный риск, рынок акций, нестандартные
заёмщики, нагрузочный портфель из 50 кредитов.

## 10. Как принять работу

| Что проверить | Как |
|---|---|
| Все автоматические тесты и проверки проходят | команды из [developer.md, раздел 17](developer.md#17-проверка-и-приёмка) |
| Каждое демонстрационное событие проходит путь до решения риск-менеджера | репетиция на стенде |
| Расчёт кредитной модели совпадает с эталоном | эталонный тест |
| Расчёт не начинается без аналитика, отчёт не публикуется без риск-менеджера | тесты процесса |
| Каждое число отчёта ведёт к расчёту | проверка отчёта, вкладка происхождения |
| Повтор расчёта даёт те же числа | проверка модулей |
| Рабочие данные не уходят во внешнюю LLM-модель | тест доступа |
| Новый модуль создаётся без правки ядра | шаблоны модулей и проверка границы |

## 11. Ограничения

- Калибровка вероятности дефолта на стенде вымышленная и помечена. Без утверждённой
  калибровки банка система показывает балл риска, но не денежные потери.
- Чувствительность акций к рынку задаётся экспертно.
- Кредитные потери клиентов лизинговой компании пока не моделируются; такие результаты
  всегда уходят на проверку.
- Залоги пока не уменьшают потери при дефолте: используется доля потерь, указанная в
  позиции.
- Уровни риска по осям (кредит, рынок, ликвидность, ковенанты, данные) не заданы банком,
  поэтому показываются как «не оценено».
- Кредитные модели работают только с рублёвыми позициями.
- Показатели сценария считаются независимыми друг от друга.
- Новый экран модуля требует пересборки интерфейса.

## 12. Словарь

| Термин | Что значит |
|---|---|
| Портфель | набор позиций: кредиты, облигации, акции |
| Позиция | одно вложение: конкретный кредит или пакет акций |
| Событие | новость или документ, влияние которого оценивается |
| Схема влияния | цепочки «событие → канал → отрасль → показатель» |
| Сценарий | насколько изменятся показатели, заданное диапазоном |
| ОКВЭД | код вида экономической деятельности компании |
| Срез портфеля | итог одного смысла: кредитные потери или рыночный результат |
| PD | вероятность дефолта заёмщика за год |
| Ожидаемые потери | средние потери от дефолтов с учётом вероятности и доли невозврата |
| Ковенант | условие кредитного договора, например предельная долговая нагрузка |
| EBITDA | прибыль до процентов, налогов и амортизации |
| ICR | во сколько раз прибыль покрывает проценты по долгу |
| Эскроу | счёт, где деньги покупателей жилья лежат до сдачи дома |
| Обратный стресс-тест | поиск силы шока, при которой нарушается условие |
| Ядро | неизменная основа системы |
| Модуль (плагин) | подключаемая часть, добавляющая тип актива, модель или помощника |
| Агент | программа с LLM или без него, выполняющая шаг процесса |
| Контур | демонстрационный или рабочий: разные данные и разрешённые LLM-модели |
