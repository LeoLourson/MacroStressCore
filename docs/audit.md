# Аудит macrostress-agent и перенос в macrostress-core

24.09.2026. Исходник — рабочее дерево `macrostress-agent` (ветка `track-av32` с незакоммиченными
изменениями). Перенесено только то, что участвует в линии «интерфейс → API → LangGraph →
Track A v3.2 → отчёт → утверждение». Старый репозиторий не изменялся.

## Итог

| | macrostress-agent | macrostress-core |
|---|---:|---:|
| Python, `src` | 208 файлов, 18 291 строка | 146 файлов, 12 770 строк |
| Интерфейсы | `ui/web` 9 034 + Streamlit 3 510 | `ui/web` 8 397 |

| Места, где нужно править при новом типе актива | ~12 в Python, TS и SQL | 1 класс + регистрация |

## Корневые проблемы

1. **Тип актива размазан по системе.** Знание о пяти типах жило в `AssetType` (Literal
   контракта), `ASSET_TYPES` модели, `if/elif` пайплайна, адаптере полей, `_REQUIRED` и
   `_DISCLOSURE` агента Exposure, `FIELD_UNITS` черновика портфеля, CHECK-ограничении БД,
   валидаторе V2 (`MONEY_FIELDS`), реестре калибровок, `FIELDS`/`ADVANCED` редактора, словарях
   подписей UI и ветке ковенанта по умолчанию в `PortfolioEditor.tsx`. Поля активов читались
   строковыми ключами с молчаливым `0.0` по умолчанию.
2. **Две расчётные линии.** Legacy-модели `models/*.py` (~2 тыс. строк), контракты
   `QuantResult`, `PortfolioResult`, `ReverseStress`, валидаторы V3/V4/V5/V6/V10/V12 и фикстуры
   жили только ради собственных регрессионных тестов. Живая линия v3.2 тянула из legacy
   `okved`, `macro_draws`, `graph_fold`, `impact`.
3. **Заглушки stage-0 как умолчание.** `Agents()` по умолчанию собирался из `Stub*`. Узлы
   различали агентов утиной типизацией (`hasattr(run_structured)`, `requires_scenario`), а
   рабочая фабрика собиралась цепочкой `track_f().with_track_a()`.
4. **Периферия вне линии.** Чат-фасад Open WebUI, Streamlit, standalone-API агентов
   `/v1/agents/*`, batch, SSE, идемпотентность без клиента, MCP `docs/search/market`,
   Qdrant, ЦБ/MOEX, n8n, Langfuse, eval/golden-раннер, нагрузочные KPI, docker-compose.
5. **Дубли.** Три реализации журнала узлов (память, сырой SQL «B6», SQLAlchemy) плюс прокси
   в `RunService`; схема БД в моделях и в замороженных копиях миграций; глубина ОКВЭД
   вычислялась дважды; `central_elasticity` — дважды; `MacroParameter` / `ScenarioParameter` /
   `Marginal`; два метода распространения шока (см. ниже).
6. **Захардкоженные значения.** Дата оценки `2026-09-11` в трёх местах, seed по умолчанию в
   узлах графа, текст `"Track B fixture"`, портфель-заглушка `"default"` в репозиториях.
7. **Слои.** MCP импортировал `msa.api.persistence`, то есть инфраструктура зависела от HTTP.

## Новая структура

- `msa/assets` — плагин `AssetModel` на семейство типов: `CorporateLoan`, `Bond`,
  `ProjectFinance`, `LeasingCompany`. Плагин объявляет входы (единица, подпись, обязательность,
  умолчание-допущение, границы), ряды, метрики ковенантов, решающие метрики, сегмент PD,
  флаги ручной проверки и содержит помесячную модель. Всё остальное читает эти объявления.
  Руководство — [asset-types.md](asset-types.md).
- `msa/engine` — расчёт без знания о типах. `run_asset` берёт модель из реестра.
- `GET /v1/asset-types` — объявления для интерфейса. Редактор портфеля, подписи типов, рядов
  и метрик приходят оттуда.
- Контракты без суффикса V2: `RiskResult`, `RiskPortfolio`, ключи `risk_results` и
  `risk_portfolio`.
- `build_agents()` — одна явная фабрика; `DurableRunRepository` — единственный журнал.
- API: 4 роутера (`runs`, `documents`, `demo`, `asset_types`) вместо 12; namespace задаётся
  путём во всех маршрутах, включая загрузку документа и проверку сценария.

## Как проверено

- **Численная эквивалентность.** 11 активов DEMO-1 и DEMO-2 на сценарии со всеми пятью
  драйверами (выручка, себестоимость, ставка, оборотный капитал, capex) посчитаны старым и
  новым кодом. Квантили, PD, ΔEL, ковенанты, Шепли, обратный стресс и траектории совпадают
  с точностью 1e-9. Отличаются только намеренно изменённые вещи: флаги допущений у A1, A5,
  EDGE-02 и отсутствие фиктивной ликвидности у лизинга A4. В этом сравнении граф не нёс
  свёрнутых эластичностей, поэтому исправление двойного масштабирования его не затрагивает.
  На графах каузального агента шоки в днях и пунктах ставки теперь дают другие, исправленные
  числа.
- **Сквозной прогон API** на SQLite и профиле `mock`: три библиотечных события → граф →
  подтверждение → расчёт → отчёт → утверждение → публикация. У каждого числа отчёта есть
  происхождение, вызовы MCP записаны. Проверены также загрузка документа, проверка сценария
  и черновик портфеля, включая отказ на неизвестное поле.
- **PostgreSQL**: базовая миграция на чистом кластере (схема `demo`, роли, GRANT), запрет
  UPDATE журнала аудита в обоих контурах, прогон с чекпоинтами в PostgreSQL.
- **Расширяемость**: тест регистрирует тип «факторинг» одним классом и считает его через
  `run_asset` и `QuantAgent` (`mcp-models`).
- `ruff`, `tsc`, сборка `ui/web`.

## Не исправлено: нужно решение

1. **F07. Охват и HHI портфеля** считаются по отобранным активам, а не по всему портфелю:
   один затронутый актив даёт охват 100 % и HHI = 1.
2. **Вырождение PD при EBITDA ≤ 0.** Признаки PD упираются в потолок, поэтому стресс не
   меняет PD и ΔEL = 0 (EDGE-01 в DEMO-2).
3. **Структурный параметр `elasticity`** проходит проверку сценария, но расчёт его
   игнорирует (флаг `scenario_parameter_unmapped`).
4. **Облигации.** Флоатер оценивается как облигация с фиксированным купоном. Шок безрисковой
   ставки цену не переоценивает. Изменение спреда пропорционально отношению PD — допущение с
   флагом.
5. **Лизинг.** Кредитные потери лизингополучателей не моделируются, результат всегда уходит
   на проверку (`leasing_ecl_missing`).
6. **Правила осей риска** не утверждены: все оси — «не оценено», пока банк не добавит
   `axis_rules` в реестр.
7. **Залоги** из профиля не участвуют в LGD: используется LGD профиля.
8. ~~Причина по рыночной оси для облигации без калибровки — английский текст из движка.~~
   Исправлено: причина по-русски.
9. ~~**Рабочий контур.** Интерфейс не показывает список рабочих портфелей, код вводится
   вручную.~~ Исправлено: `GET /v1/portfolios`, список в интерфейсе.
10. **Standalone-API агентов** (ТЗ §8, KPI K16/K17) удалено как неиспользуемое. Если оно нужно
    для приёмки по ТЗ, его стоит вернуть поверх `build_agents()` и плагинов.
