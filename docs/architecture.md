# Архитектура

Контракты и устройство ядра подробно описаны в [platform.md](platform.md), расширение
плагинами — в [plugins.md](plugins.md). Здесь — линия прогона и слои.

## Линия прогона (процесс `stress_test`)

```
ui/web ── POST /v1/{demo/}runs ──► RunService (очередь, 5 потоков, журнал в api_job)
                                     │  фиксирует: процесс, плагины и версии, позиции,
                                     │  модели, снимок данных, дату оценки
LangGraph, собран из WorkflowSpec     ▼
 ingest ──────────── текст → адресуемые фрагменты (SHA-256)
 [after_event_parsed] ───────────────────────────── точка расширения
 causal_agent ────── LLM: граф влияния, паспорт события, сценарий по факторам реестра
 validate_causal ─── V1 контракт, V2 факторы и единицы, V7 ацикличность, V8 источники
 [before_scenario_approval] ─────────────────────── точка расширения
 human_fix_graph ─── аналитик подтверждает граф и сценарий              ← остановка
 exposure_profiler ─ какие позиции достигнуты (граф → отрасль или прямой фактор),
                     данные на дату оценки из снимка                     → mcp-portfolio
 draw_macro ──────── общая матрица Соболя R × N, собственные шоки, scenario_id
 quant_agent × N ─── модель плагина для каждой позиции (Send)          → mcp-models.run_model
 aggregate ───────── срезы портфеля по совместным реализациям, V11
 [after_calculation] ────────────────────────────── точка расширения
 advisory_agent ──── правила плагинов, отчёт с числами из дерева метрик, V9
 [before_report] ────────────────────────────────── точка расширения
 human_approval ──── риск-менеджер утверждает / возвращает / отклоняет  ← остановка
 publish
```

Агенты плагинов подключаются к точкам в квадратных скобках, пишут только в своё
пространство состояния и не лежат на пути в обход остановок. Каждый узел пишет
результат в журнал (`run_node_result`) в отдельной транзакции, с версией агента и хешем
входов. Чекпоинты LangGraph хранятся в PostgreSQL. Перезапущенный процесс продолжает
прогон с последнего завершённого узла без повторных вызовов LLM.

Процесс `explain_results` (вопрос по рассчитанному прогону): `explain` →
`[after_explanation]`. Агент — ограниченный цикл LLM ↔ `mcp-runs`; журнал — под узлом
`explain/<id>` того же прогона.

## Слои и зависимости

```
                                   ядро                                 │   плагины
api ──► graph ──► agents ──► engine ◄── plugin_sdk (calc, report, ...) ◄─┼── plugins (credit,
 │        │         │           ▲            ▲                          │   equity, market,
 │        │         └──► mcp ───┘       platform (реестр) ─ находит ───►│   research)
 │        └──► workflows (встроенный core: процессы, агенты, MCP ядра)  │
 └──► db ◄── mcp            reporting ──► platform                      │
contracts ◄── все (и плагины)                                            │
```

Граница проверяется автоматически ([plugins.md, раздел 8](plugins.md#8-границы-и-совместная-работа)):
ядро не импортирует `msa.plugins`, плагины импортируют только `msa.plugin_sdk`,
`msa.contracts` и свой пакет (и базовый плагин `market`), ядро не называет плагины в коде.

- **contracts** — pydantic-контракты обмена: доменная модель (`Party`, `Instrument`,
  `Position`, `PortfolioBundle`), `DataSnapshot`, `TransmissionGraph`, `MacroParameter`,
  `CalculationResult`, `PortfolioResult`, `Report`, `Explanation`. Тип инструмента — строка,
  проверяемая по реестру.
- **plugin_sdk** — всё, что объявляет и использует плагин: `Plugin`, спецификации (типы,
  метрики, факторы, срезы, виды, правила, MCP-серверы), `CalculationModel`, `AgentPlugin`,
  `WorkflowSpec`, хелперы результата, вычисления ядра (`calc`), помощники отчёта
  (`report`), промпты (`prompts`), помощники тестов и проверка соответствия (`testing`).
- **platform** — реестр: загружает встроенное объявление `core` (`msa/workflows`), затем
  находит плагины в `msa.plugins`, проверяет объявления, строит каталоги.
- **plugins** — единственное место, где известны типы инструментов, их математика и
  предметные агенты. `credit/math/` — помесячные модели семейств, календарь, метрики, PD и
  ожидаемые потери, ковенанты, оси риска, обратный стресс; `market/fx.py` — валютный
  фактор. У каждого плагина свои тесты, демо-данные и README в его папке.
- **engine** — расчёт без знания типа: снимок и разрешение данных, сценарий и общие
  реализации, передача шока по графу, диспетчер моделей, агрегация по срезам, Шепли.
- **agents** — агенты прогона ядра и агент объяснения; `build_agents()` собирает рабочий
  набор.
- **graph** — компилятор процессов, узлы, журнал, остановки, чекпоинты.
- **mcp** — серверы из реестра (ядра: `mcp-portfolio`, `mcp-models`, `mcp-runs`; плагинов:
  `mcp-<plugin_id>.<имя>`), шлюз, аудит вызовов и шлюз агента, ограниченный объявленными
  инструментами.
- **reporting** — дерево метрик, отчёт без собственных чисел, правила, трасса.
- **db** — таблицы (одинаковые для рабочего контура и схемы `demo`), репозитории,
  миграция `p0001`.
- **api** — HTTP. Контур задаётся путём: `/v1/demo/...` — демо, `/v1/...` — рабочий.
- **cli** — `msa-plugin`: шаблоны плагинов, проверка, демо-расчёт, манифест UI.

## Контуры и LLM

- **demo** — синтетические портфели, снимок `SYNTHETIC-2026-09-11`, событийная библиотека, схема
  `demo`, синтетическая калибровка PD `demo-synthetic-2026-09` (каждый результат помечен).
  Портфели и снимок собирает `demo/catalog.py` из заголовков в `demo/` и частей плагинов
  (`src/msa/plugins/<id>/demo_data/`).
- **production** — портфели банка (`ops/load_portfolio.py`, `POST /v1/portfolios`) и его
  снимки; калибровка из `MSA_CALIBRATION_REGISTRY`. Без калибровки результат — индекс
  риска без денежной потери. Внешняя LLM (DeepSeek) в рабочий контур не допускается ни для
  прогонов, ни для объяснений (409).
- Профиль LLM — `MSA_LLM_PROVIDER`: `local` | `deepseek` | `mock`. Вызов инструментов
  включён для `local` и `deepseek`; `MSA_LLM_TOOL_CALLING` переопределяет это значение.
- Агенты плагинов, выключенные по умолчанию, — в запросе прогона (`agents`) или в
  `MSA_AGENT_PLUGINS`.

## Дата оценки

Дата оценки берётся из запроса, иначе из портфеля (`portfolio.as_of`), иначе — сегодняшняя.
Данные снимка используются только датированные не позже неё. Календарь расчёта
начинается с конца следующего месяца.
