## Как проверяли

- **Вся линия прогона**, как в демо-контуре: текст события → граф и сценарий → V1, V2, V7,
  V8 → остановка аналитика (с настоящей проверкой сценария и покрытия,
  `scenario_violations`, `scenario_coverage`) → позиции, которых достигло событие →
  общая матрица реализаций → модели плагинов через `run_model` → срезы → отчёт с правилами
  R1–R5, E1–E2 и V9 → утверждение → публикация ([`demo/sanity/line.py`](../demo/sanity/line.py)).
  Калибровка PD — синтетическая `demo-synthetic-2026-09`; 8192 реализации (8 реплик ×
  1024); зерно 20260911; горизонт 12 месяцев; дата оценки 11.09.2026.
- **Заменены только люди и LLM.** Ответ каузального агента — граф и сценарий синтетического
  события (то, что подтвердил бы аналитик); аналитик подтверждает их без правок;
  риск-менеджер утверждает отчёт. Качество LLM эти проверки не оценивают.
- **Портфели** вводятся тем же путём, что редактор (`msa.api.portfolio_draft.build`), и
  проверяются так же, как при сохранении через API (`check_bundle`). Каждое число — допущение
  автора `sanity:synthetic`.
- **Ожидание** каждой проверки записано в коде до прогона как утверждение, которое аналитик
  принял бы без знания кода; вердикт вычисляется автоматически. Где ожидание неоднозначно
  (например, знак влияния падения нового бизнеса на лизингодателя), вердикт не выносится.
- Числа демо-калибровки не являются оценками риска. Проверяются только структурные
  свойства: знак, порядок, пропорции, равенства, изоляция.

### Что соответствует здравому смыслу

- **Направление и сила.** Нулевой шок даёт ΔEL = 0 и ΔPD = 0 (A1); выручка −10 % → ΔEL
  +4,27, +10 % → −2,54 (A2); ΔEL растёт с силой шока: 1,83 / 4,27 / 12,65 / 33,95 / 288,3 при
  −5 / −10 / −20 / −30 / −45 % (A3); каждый неблагоприятный драйвер увеличивает ΔEL (A4).
- **Качество заёмщика.** Базовая PD и ΔEL растут с долгом/EBITDA: PD 0,82 → 6,74 %, ΔEL
  0,29 → 11,25 (A6); тонкая маржа при равных ICR и долге теряет больше: ΔEL 6,96 / 4,05 / 3,28
  / 2,72 при марже 5 / 10 / 15 / 25 % (A7); перенос затрат в цену смягчает удар (A8), а
  эластичный спрос мешает ему (A9); рост ставки сильнее бьёт по закредитованному (A5).
- **Пропорции.** ΔEL строго пропорциональна EAD и LGD (A10, A11); заёмщик ×10 по всем
  денежным показателям даёт те же PD и ΔEL (A12); ΔEL не превышает LGD·EAD − EL базы (A18).
- **Граф.** Событие по 23.61 не достигает строительства, ИТ и пищевой промышленности (B1);
  узел раздела «23» достигает своих классов (B3); доля канала 0,25 / 0,5 / 1 даёт ровно
  0,9^доля − 1 (B4); ΔEL убывает с лагом, лаг 12 при горизонте 12 даёт 0 (B5); два канала по
  −5 % равны одному −9,75 % (B7); событие мимо портфеля публикуется с текстом «Событие не
  затрагивает позиции портфеля» (B9); шок в днях для выручки отклоняется на остановке (B12).
- **Портфель.** Один общий фактор — P95 среза равна сумме P95 (C1); дробление позиции и
  добавление незатронутой позиции не меняют срез (C2, C3); прогоны воспроизводимы и не зависят
  от порядка позиций (C5); отрицательный вклад выигравшего заёмщика не теряется (C7); акция
  эмитента, которого задело кредитное событие, без шока не считается «с нулём», а аналитика
  просят задать шок явно (C9).
- **Акции.** Нулевой шок — ровно 0; бета, количество, индекс, отрасль, валюта, дивиденды
  дают точные аналитические значения (D1–D7, D11); P95 одиночного остаточного риска 38,91 при
  аналитических 38,95 (D8).
- **Прочие семейства и отчёт.** Облигация дешевеет при ухудшении эмитента (E1); проект
  теряет при падении продаж, перерасходе и росте ставки (F1, F2); лизинг — при дорогом
  фондировании и росте расходов (G1, G2); рекомендации: без шока — нет, лёгкий — наблюдение,
  тяжёлый — реструктуризация и сокращение лимита, улучшение — нет, ковенант — R2 (H1–H5).
- **Ввод.** LGD 1,5 и EAD −100 отклоняются при сохранении портфеля; pass-through 1,5 и
  положительная эластичность останавливают позицию с указанием поля (I1, I2, I4, I5).
- **Истории.** Ставка +5 п.п. (S1), девальвация (S2), ипотека (S3), обвал рынка (S5) дают
  ожидаемые знаки и порядок: например, в S2 импортёр ΔEL +207, экспортёр −2,7, долларовая
  акция +25 %; в S5 потери растут с β: девелопер 31,2 %, банк 27,1 %, нефть 14,8 % (с
  дивидендом 8 %).

## Находки

### 1. B2, S4. Событие по одному классу ОКВЭД бьёт по всем классам того же раздела

**Прогон.** Граф: выручка отрасли 23.61 (бетонные изделия) −10 %. Портфель: заёмщики 23.61,
23.51 (цемент), 23.99.

**Результат.** Рассчитаны все три; у каждого выручка −10 % — полный шок 23.61. В истории S4
(утильсбор на спецтехнику, узел 64.91 «лизинг») акция банка 64.19 попадает под событие, и
остановка аналитика требует задать для неё шок рынка или отрасли; без этого прогон не идёт.

**Почему.** `okved_depth` засчитывает совпадение первых двух цифр
([okved.py](../src/msa/engine/okved.py#L1)); позиция считается достигнутой при любой
глубине > 0 ([exposure.py:55](../src/msa/engine/exposure.py#L55)), а шок берётся с
самого глубокого совпавшего узла ([graph_signal.py:66](../src/msa/engine/graph_signal.py#L66)).
Когда в графе есть только 23.61, для 23.51 «самым глубоким» оказывается он.

**Чем грозит.** Лишние позиции получают полный шок чужого класса. Аналитика заставляют
вводить нули для посторонних бумаг.

### 2. A14. Валютный шок бьёт по всей себестоимости; доля импорта не используется

**Прогон.** Два одинаковых заёмщика с долей импорта 0 и 0,8; курс (`credit.fx`) +20 %.

**Результат.** ΔEL одинакова — 372,9 при максимуме LGD·EAD = 450; флага нет. Заёмщик без
импорта почти дефолтен: переменные затраты растут на 20 %, EBITDA падает с 1 800 до
12 000 − 8 400 × 1,2 − 1 800 = 120.

**Почему.** Семейство операционных компаний умножает на курс всю себестоимость:
`unit_cost = compound(cogs, logistics, fx)`
([corporate.py:173](../src/msa/plugins/credit/families/corporate.py#L173)). Доля импорта
сохраняется в профиле ([profile.py:170](../src/msa/plugins/credit/profile.py#L170)), но ни
одно семейство её не читает, хотя подсказка редактора обещает «Используется для валютного
шока» ([editor_help.py:7](../src/msa/plugins/credit/editor_help.py#L7)).

**Чем грозит.** Любой валютный сценарий многократно завышает потери неимпортёров. В S2 импортёр
с долей 80 % получает шок как при 100 %.

### 3. A17. Ковенант + сценарий с нулевым центром = позиция не рассчитана

**Прогон.** Выручка треугольно −5 / 0 / +5 %. Заёмщик без ковенанта и такой же с ковенантом
ICR ≥ 2.

**Результат.** Без ковенанта: P5/P95 ΔEL −1,00 / +1,20. С ковенантом: `failed`,
`model_error:ValidationError` — «ReverseStressDirection.norm: Input should be greater than 0».
Так же падает точечный нулевой шок.

**Почему.** Направление обратного стресс-теста строится из центральных значений сценария
([position_risk.py:448](../src/msa/plugins/credit/position_risk.py#L448)). При нулевом центре его норма
равна 0, а контракт требует положительную
([contracts.py:98](../src/msa/plugins/credit/contracts.py#L98),
[position_risk.py:503](../src/msa/plugins/credit/position_risk.py#L503)).

**Чем грозит.** Симметричные сценарии («курс ±10 %») и нулевые шоки не считаются для любого
заёмщика с ковенантом. Позиция выпадает из среза, срез становится `incomplete`.

### 4. A16. Заёмщик без долга получает PD 50 %

**Прогон.** Два заёмщика: валовый долг 0 (чистый долг −500, деньги 500) и валовый долг 1 000
(чистый долг −2 000, деньги 3 000).

**Результат.** Базовая PD 0,500 и 0,0078 соответственно. Флаг `cash_interest_nonpositive`
есть, но статус у обоих одинаковый (`needs_review`), и оба входят в срез по правилу
S19-SYNTHETIC-REVIEW.

**Почему.** При нулевых процентах ICR не определён
([metrics.py:60](../src/msa/plugins/credit/math/metrics.py#L60)), и признак покрытия берёт
потолок 2,5 — худшее значение ([credit.py:154](../src/msa/plugins/credit/math/credit.py#L154)).
Долг/EBITDA отрицателен и даёт признак 0
([credit.py:145](../src/msa/plugins/credit/math/credit.py#L145)). В синтетической калибровке
z = −5 + 2 · 2,5 + 0,8 · 0 + 1,5 · 0 = 0, PD = 1 / (1 + e⁰) = 0,5
([demo-synthetic-2026-09.json:21](../src/msa/plugins/credit/registries/demo-synthetic-2026-09.json#L21)).

**Чем грозит.** Заёмщик, у которого на дату отчётности не было процентного долга (например,
при первом кредите), получает PD как проблемный.

### 5. B8. Общий узел фактора умножает шок на число отраслей

**Прогон.** Выручка −10 % по отраслям 23.61, 41.20 и 46.63: (а) отдельный узел фактора на
каждую отрасль, как требует промпт; (б) один общий узел «выручка».

**Результат.** Выручка заёмщика 23.61: (а) −10 %, (б) −27,1 % = 0,9³ − 1; ΔEL 4,27 и 25,17.
Предпросмотр аналитика показывает те же −27,1 %.

**Почему.** Сигнал узла фактора — сумма сигналов всех входящих рёбер
([transmission.py:267](../src/msa/engine/transmission.py#L267)), и позиция читает этот узел
целиком ([graph_signal.py:35](../src/msa/engine/graph_signal.py#L35)). Раздельные узлы
требует только промпт
([causal-v3.txt:15](../src/msa/prompts/templates/causal-v3.txt#L15)); валидаторы такой граф
пропускают. Тестовый двойник каузального агента сам строит общий узел
([tests/support.py:160](../tests/support.py#L160)).

**Чем грозит.** Добавление в событие новых отраслей усиливает шок для уже затронутых. Может ли
аналитик собрать такой граф в редакторе интерфейса, не проверялось [не подтверждено].

### 6. B6. «Продажи упадут на 35 %» превращается в −25,9 %

**Прогон.** (а) Канал «продажи» −0,35, ребро отрасль → выручка со знаком +1. (б) Канал
«падение продаж» +0,35, знак −1.

**Результат.** Выручка (а) −35 %, (б) −25,9 % = 1 / 1,35 − 1; ΔEL 60,6 и 22,4. Предпросмотр
аналитика показывает те же числа.

**Почему.** Относительный шок входит в граф как ln(1 + x)
([transmission.py:283](../src/msa/engine/transmission.py#L283)). Знак −1 переворачивает
логарифм, и +35 % превращается в 1/1,35. Вариант (б) — ровно то, что предписывает промпт:
канал формулируется как растущий, число измеряет канал «как сформулирован», убывание задаётся
знаком −1 ([causal-v3.txt:20](../src/msa/prompts/templates/causal-v3.txt#L20),
[:26](../src/msa/prompts/templates/causal-v3.txt#L26)).

**Чем грозит.** При падениях в десятки процентов потери занижаются в разы. Как часто LLM
выбирает вариант (б) на практике — не проверялось [uncertain].

### 7. D12, D13. Остаточные шоки акций зависят друг от друга и от рынка

**Прогон.** D12: две разные акции, только остаточный риск σ = 30 %. D13: одна акция, β = 1,
рынок MOEX треугольно ln 0,8 / 0 / ln 1,2, σ = 30 %; остаток восстановлен как
ε = ln(V_T / V_0) − f_m.

**Результат.** D12: корреляция потерь двух акций по репликам +0,83, −0,69, +0,82, +0,46,
−0,41, +0,91, +0,76, −0,63, по всем точкам +0,26 (при независимости — около 0 ± 0,03). D13:
ρ(f_m, ε) по репликам от −0,74 до +0,66, по всем точкам −0,46. Та же зависимость в функции
ядра: χ² на сетке 16 × 16 для пары остатков — 15 360 при 255 степенях свободы.

**Почему.** Остаток каждой бумаги — одномерная последовательность Соболя со своим
перемешиванием ([scenario_set.py:150](../src/msa/engine/scenario_set.py#L150)). Рыночный
фактор с одним параметром — тоже первое измерение Соболя
([scenarios.py:104](../src/msa/engine/scenarios.py#L104)). Точки с одним номером у разных
перемешиваний одной последовательности не независимы. Одномерные распределения при этом
верны (D8).

**Чем грозит.** Хвосты рыночного среза искажены в обе стороны. В D13 P95 потери 38,9 против
40,9 при независимом остатке (среднее 50 случайных перестановок остатка, диапазон
40,2–41,3). В D12 P95 среза двух акций 62,0 против 56,2 (диапазон 54,9–57,3). Прохождение D9
(«диверсификация есть», отношение 0,80) поэтому случайно.

### 8. C8. Соседние зёрна делят 7 из 8 реплик

**Прогон.** Выборка сценария для зёрен 1 и 2 и прогоны линии с ними.

**Результат.** 7 из 8 реплик совпадают; P95 среза в обоих прогонах 19,50190626 — совпадает до
10 знаков. С зёрнами 1, 101 и 20260911 разброс P95 — 0,21 % (C6).

**Почему.** Реплика r зерна s перемешивается зерном s + r
([scenarios.py:104](../src/msa/engine/scenarios.py#L104)), поэтому реплика r + 1 зерна s —
это реплика r зерна s + 1.

**Чем грозит.** Проверка устойчивости «перезапуском со следующим зерном» ложно показывает
нулевую численную погрешность.

### 9. D10. Одна бумага двумя строками редактора считается двумя независимыми

**Прогон.** Две строки с тикером AAA по 100 млн руб., σ = 30 %.

**Результат.** P95 среза 56,5 при сумме P95 позиций 77,8 (отношение 0,73). Для одной бумаги
ожидалось 1.

**Почему.** Редактор создаёт отдельный инструмент на каждую строку
([portfolio_draft.py:102](../src/msa/api/portfolio_draft.py#L102)). Остаток привязан к
инструменту, а не к тикеру ([equity/model.py:214](../src/msa/plugins/equity/model.py#L214)).
Документация обещает одинаковые реализации для двух позиций одной бумаги
([platform.md:70](platform.md#L70)); это выполняется, только если позиции ссылаются на один
`instrument_id` (импорт бандла).

**Чем грозит.** Появляется ложная диверсификация.

### 10. B10. Неопределённость эластичности ребра не входит в распределение

**Прогон.** Точечный шок −10 %; эластичность отрасль → фактор (а) 1, (б) треугольная
0,5 / 1 / 1,5.

**Результат.** Ширина P5–P95 ΔEL — 0 в обоих случаях.

**Почему.** Из распределения эластичности берётся только центр
([graph_adapter.py:75](../src/msa/engine/graph_adapter.py#L75)); реализации его не
разыгрывают. Промпт при этом просит задавать неопределённые эластичности треугольными
([causal-v3.txt:20](../src/msa/prompts/templates/causal-v3.txt#L20)).

**Чем грозит.** Интервал P5–P95 уже, чем заявленная неопределённость графа.

### 11. I3. Остаточная волатильность 20 (то есть 2 000 %) принимается

**Прогон.** Акция на 100 млн руб., `residual_volatility = 20` (ошибка «20 вместо 0,2» при
вызове API; интерфейс переводит проценты в доли сам).

**Результат.** Рассчитано без замечаний: потеря P95 — 100 из 100, P5 — «доход»
1,95 · 10¹⁶ млн руб.

**Почему.** Значение читается без проверки диапазона
([equity/model.py:208](../src/msa/plugins/equity/model.py#L208)).

### 12. A13. CCF принимается и молча не используется

**Прогон.** CCF 1 и 0,5 у одинаковых заёмщиков.

**Результат.** ΔEL одинакова (4,273), флага нет.

**Почему.** CCF сохраняется в профиле
([profile.py:169](../src/msa/plugins/credit/profile.py#L169)), но расчёт ожидаемых потерь
берёт EAD как есть. Подсказка редактора описывает CCF как долю обязательства, которая будет
использована к дефолту.

## Наблюдения без вердикта

- **Шок −100 % (B11)** принимается на остановке аналитика. Позиция затем не рассчитывается
  с понятной причиной «relative shock for channel must be greater than -1». Нижняя граница
  −1 объявлена у кредитных факторов (`FactorSpec.lower_bound`,
  [specs.py:82](../src/msa/plugin_sdk/specs.py#L82)), но проверка сценария её не читает.
- **Лаг (B5)** снижает ΔEL круче доли незатронутых месяцев: лаг 3 из 12 месяцев уменьшает ΔEL
  с 12,6 до 3,8. Причина — годовой пересчёт LTM в первых месяцах горизонта (флаг
  `ltm_annualised`): без лага месячный шок сразу входит в годовой ICR.
- **Проект (S1)** почти не чувствителен к ставке +5 п.п.: ΔEL 0,004 % EAD. Это свойство
  синтетической калибровки сегмента `project_finance` (z = −4,5 + 0,6 · r_icr).

## Ограничения этой проверки

- LLM, база данных, HTTP-слой API и интерфейс не участвовали. Граф и сценарий события заданы
  напрямую, как их подтвердил бы аналитик.

  структурные свойства, а не уровни риска.
- Первый прогон был на Linux, повторный — на Windows. Вердикты от платформы не зависят:

- Ожидания — суждения здравого смысла. Список проверок не доказывает отсутствие других
  ошибок.
