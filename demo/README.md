# Демо-каталог

Портфели, снимки данных и события, которые `msa.ps1 up` загружает в демо-контур. Каждое событие
привязано к своему портфелю: интерфейс подставляет его, если аналитик не выбрал другой. В профиле
`mock` каузальный шаг отвечает готовым графом и сценарием из события (`mock_answer`).

MOEX ISS, проектная декларация, раскрытие эмитента. Экспертные оценки помечены автором, факт
после события лежит рядом для сверки.

|---|---|---|---|
| `etalon/` ГК «Эталон» | `ETALON-DEC-2023` (снимок `ETALON-2023-12-31`), `ETALON-JUN-2024` (`ETALON-2024-06-30`): кредит группе, акция ETLN и проектное финансирование ЖК «Зелёная Река» (Омск) | `HIST-ETALON-MORTGAGE-2023-12` ужесточение массовой льготной ипотеки 23.12.2023; `HIST-ETALON-MORTGAGE-2024-07` завершение программы 01.07.2024 | отчётность, котировки, калибровка проекта и сверка с фактом — [research/](historical/etalon/research/) |

## Устройство

Каждая часть каталога — коллекция: папка с `events/`, `portfolios/` и `snapshots/`.
Синтетическая коллекция одна, историческая — по одной на случай.

```text
demo/
  synthetic/                    вымышленные компании и новости (metadata.synthetic: true)
    events/                     события, по файлу на событие (с mock_answer для профиля mock)
    portfolios/                 заголовки портфелей: {"portfolio": {...}} без позиций
    snapshots/                  заголовки снимков данных без items
    story_catalog.json          компании и книги деловых историй (вход build_catalog.py)
  historical/                   настоящие события и публичные данные (metadata.synthetic: false)
    etalon/                     ГК «Эталон», ипотека 2023–2024
      events/ portfolios/ snapshots/
      sources.json              источники случая
      research/                 сбор данных: заметки, котировки, отчётность, скрипты, сверка с фактом
    afk-systema/                «дочки» АФК «Система», ключевая ставка 25.10.2024
      events/ portfolios/ snapshots/
      sources.json
      research/                 (raw/ — страницы MOEX ISS)
    mortgage-2023/              льготная ипотека 23.12.2023 для синтетического MULTI-ASSET
      event.json                событие для MULTI-ASSET; в библиотеку его заносит demo/pilot.py
      sources.json
  sanity/                       проверки здравого смысла: python -m demo.sanity
  catalog.py                    сборка портфелей и снимков из заголовков и частей плагинов
  build_catalog.py              генератор синтетических портфелей и ответов профиля mock
  build_etalon.py               генератор файлов случая historical/etalon
  build_pilot_afk.py            генератор файлов случая historical/afk-systema
  seed_demo.py                  загрузка каталога в демо-контур
  pilot.py, pilot_afk.py        занесение исторических событий в библиотеку стенда
```

Части портфелей и снимков лежат в плагинах по тому же пути коллекции и под тем же именем файла:
`src/msa/plugins/<id>/demo_data/<коллекция>/portfolios/<portfolio_id>.json` (`parties`,
`instruments`, `positions`) и `src/msa/plugins/<id>/demo_data/<коллекция>/snapshots/<snapshot_id>.json`
(`items`), где коллекция — `synthetic` или `historical/<случай>`. Строки деловых историй —
`demo_data/synthetic/story_rows.json`.

Заголовок и части сводит `demo/catalog.py`, читая плагины в порядке реестра. Одинаковая запись
из двух плагинов допустима. Ошибкой считаются:

- разные записи под одним идентификатором;
- часть в другой коллекции, чем её заголовок;
- `metadata.synthetic`, не совпадающий с коллекцией.

Плагин может положить в свою `demo_data/<коллекция>/` и собственный заголовок портфеля или снимка.

Генераторы переписывают свои файлы; с `--check` только сверяют:

```powershell
uv run --frozen python -m demo.build_catalog [--check]     # synthetic/ и ответы mock
uv run --frozen python -m demo.build_etalon [--check]      # historical/etalon/
uv run --frozen python -m demo.build_pilot_afk [--check]   # historical/afk-systema/
uv run --frozen python -m demo.sanity M                    # каждое событие на своём портфеле
```
