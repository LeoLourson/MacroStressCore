# Проверки здравого смысла

Синтетические портфели и события, на которых линия прогона проверяется так, как её проверил
бы аналитик без знания кода: больший шок даёт большие потери, незатронутая отрасль остаётся
незатронутой, удвоенная сумма под риском удваивает потери, диверсифицированный портфель
теряет в хвосте меньше суммы частей. Разбор результатов — в
[docs/sanity-report.md](../docs/sanity-report.md), таблица последнего прогона — в
[results.md](results.md), числа — в [results.json](results.json).

```powershell
uv run python -m sanity                     # все проверки, ~45 с
uv run python -m sanity A B6 S              # группа A, проверка B6, группа S
uv run python -m sanity --json sanity/results.json --markdown sanity/results.md
```

Код выхода всегда 0: это оценка, а не шлюз CI. Каталог не входит в `pytest` и в границы
`lint-imports` (он вне пакета `msa`).

## Что запускается

Каждая проверка строит свои портфели и события и прогоняет **всю линию** процесса
`stress_test` (`sanity/line.py`): текст события → граф и сценарий → проверки V1–V8 →
остановка аналитика (с настоящей проверкой сценария и покрытия) → позиции, которых достигло
событие → общая матрица сценариев → модели плагинов → срезы портфеля → отчёт с
рекомендациями → утверждение → публикация. Демо-контур: синтетическая калибровка PD
`demo-synthetic-2026-09`, 8192 реализации, зерно 20260911, горизонт 12 месяцев.

Заменены только люди и LLM: ответ каузального агента — это граф и сценарий синтетического
события (то, что подтвердил бы аналитик), аналитик подтверждает их без правок, риск-менеджер
утверждает отчёт. Качество LLM эти проверки не оценивают.

Портфель вводится тем же путём, что в редакторе (`msa.api.portfolio_draft.build`), и
проверяется так же, как при сохранении через API (`check_bundle`).

## Файлы

| Файл | Что там |
|---|---|
| `build.py` | базовый заёмщик `BORROWER`, строки редактора `loan()` и `share()`, `portfolio()`; событие `Event` из путей `Link` (канал → отрасль → фактор) и `Direct` (канал → прямой фактор), параметр `shock()` |
| `line.py` | прогон линии на портфеле и событии, результат `Outcome` |
| `lab.py` | чтение результата (ΔEL, PD, выручка, срезы, рекомендации) и `Verdict` |
| `checks.py` | проверки по группам A–I и сценарии-истории S на диверсифицированной книге |
| `__main__.py` | запуск, вывод, `--json`, `--markdown` |

## Новая проверка

```python
@check("A99", "Название", "Что должно получиться по здравому смыслу",
       portfolio="какой портфель", event="какое событие")
def a99():
    o = one([loan("L", "23.61", net_debt=6000.0)], credit_event("A99", value=-0.15))
    d = delta_el(o, "L")
    return Verdict(d is not None and d > 0, f"ΔEL {fmt(d)}", {"delta_el": d})
```

Ожидание формулируется до прогона. Если вопрос неоднозначен (например, знак влияния падения
нового бизнеса на лизингодателя), проверку лучше не заводить или вернуть `Verdict(None, …)`.
